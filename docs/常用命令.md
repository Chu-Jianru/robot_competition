# Windows 常用命令速查

更新：2026-11-03。项目根目录 `E:\robot_competition`，下面使用 **PowerShell**。

## 最简用法：双击菜单

双击 `E:\robot_competition\tools\日常工具.cmd`，输入数字并回车；无需配置变量或复制长命令。

- `1` 看画面、拍照片：窗口内 S 保存，Q 退出。
- `2` 看 tag 和台架红块检测。
- `3` 统计 60 帧 tag 检出情况。
- `4` 标定场地四角：弹出文件选择框选原图，依次点左上、右上、右下、左下的地面内角，回车保存，然后显示校正结果。
- `5` 按标定查看车辆位置，需先完成 4。
- `6` 查看已有识别结果，再选无车/带车批次。
- `7` 标注照片，再选无车/带车批次。
- `8` 检查手机 USB 连接。
- `9` 打开底盘工作台，随后连接和运动由人在面板中操作。
- `0` 退出。

最常用顺序：**1 拍图 → 4 标定 → 5 看定位**。只看 tag 选 2。实时入口尚未接入最新离线整场分割/曝光补检；标定按当前机位重新保存。菜单中的相机工具退出后才会回到菜单，不并行启动第二个客户端；另开原生 scrcpy 时仍需先自行退出。

终端中仅需一条命令：

```powershell
E:\robot_competition\tools\日常工具.cmd
```

下面保留完整参数，供排查与批处理时使用。

命令按当前脚本参数核对；整理本文时只读源码与帮助，没有启动相机、底盘、串口或 Gazebo。同一时间只运行一个摄像头客户端。结束相机程序后再启动下一个。

## 1. 每次打开新 PowerShell，先执行

```powershell
Set-Location 'E:\robot_competition'
$robotScrcpy = 'E:\scrcpy\scrcpy-win64-v5.0.1'
$robotPython = Join-Path $robotScrcpy '.venv\Scripts\python.exe'
$robotSession = Get-Date -Format 'yyyyMMdd_HHmmss'
$robotCaptureDir = Join-Path $PWD "windows\captures_hi\$robotSession"
$robotCalib = Join-Path $PWD 'windows\field_calib.json'
```

以下 `$robotPython` 等变量只在当前 PowerShell 窗口有效，不需要激活虚拟环境。新一轮采集可重新设置 `$robotSession`、`$robotCaptureDir`，避免混入不同机位的图。

## 2. 检查手机 USB 是否连上

```powershell
& "$robotScrcpy\adb.exe" devices -l
```

看到 `device` 才是已授权；`unauthorized` 时在手机上确认 USB 调试授权。没有设备先检查数据线和 USB 调试。

需要完整链路诊断时，先退出其他相机客户端，再执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\windows\check_link.ps1 -ScrcpyDir $robotScrcpy
```

该体检会推送 scrcpy 服务端并实际取流，不是纯离线检查；不发送电机命令。

## 3. 只看原生 scrcpy 相机画面

```powershell
& "$robotScrcpy\scrcpy.exe" --video-source=camera --camera-facing=back --max-size=1280 --camera-fps=30 --no-audio
```

只预览，不运行项目识别。正式标定使用下面 Python 取流保存的原图，确保与实际运行的旋转、分辨率一致。

## 4. 高分辨率取图、保存标定原图（不动车）

```powershell
& $robotPython .\windows\capture_hi.py --scrcpy-dir $robotScrcpy --rotate 90 --max-size 1280 --no-fallback --out $robotCaptureDir
```

- `S` 保存原始分辨率 PNG；`R` 旋转画面；`Q/Esc` 退出。
- 原图名为 `hi_时间_宽x高.png`，保存到当前 `$robotCaptureDir`。
- `--no-fallback` 禁止自动降低分辨率，避免标定前后取流尺寸悄悄改变；若该档启动失败，明确调整档位后重新标定。
- 最终旋转方向要保持一致；若需要换 `--rotate`，后续命令也相应修改。

## 5. 实时查看 tag 与旧版红块台架检测（不动车）

先退出第 4 节的客户端：

```powershell
& $robotPython .\windows\capture_hi.py --scrcpy-dir $robotScrcpy --rotate 90 --max-size 1280 --no-fallback --bench --detect-hz 10 --out $robotCaptureDir
```

`S` 保存原图和标注图；`Q/Esc` 退出。控制台显示 tag 像素边长、局部 mm/px 和旧版红块候选。**这不是最新整场粘连分割程序**，也不包含 `photo_tag.py` 的最新离线曝光补检。

连续统计 60 帧，先让车辆静止，再执行（不要同时开上述预览）：

```powershell
& $robotPython .\windows\live_bench.py --scrcpy-dir $robotScrcpy --rotate 90 --max-size 1280 --frames 60
```

结果默认写 `windows/captures_hi/live_时间/`，包括 `frames.csv` 和最佳标注图。统计 tag 检出率、像素抖动、处理耗时等；它不是全场毫米位置精度验收，退出码也不等同于达到全部质量门槛。

## 6. 当前机位的场地四角标定（不动车）

先用第 4 节按 `S` 保存完整场地原图，然后退出取流窗口。以下取当前采集目录中最新原图：

```powershell
$robotFrame = Get-ChildItem -LiteralPath $robotCaptureDir -Filter 'hi_*x*.png' | Sort-Object LastWriteTime -Descending | Select-Object -First 1
if (-not $robotFrame) { throw '请先用 capture_hi 按 S 保存完整场地原图。' }
& $robotPython .\windows\field_view.py calibrate $robotFrame.FullName --out $robotCalib
```

**此工具的点选顺序固定为画面左上→右上→右下→左下**，点地面内角，不点围栏上沿。右键撤销，四角齐全后回车保存，Esc 取消。它不同于照片标注入口的 K（后者沿周边点四角、起点不限）。

统一取景方向时尽量让黄区在画面上方、蓝区在下方；此实时标定工具按画面方向建立坐标，不会自动按蓝黄旋转坐标。正式接策略前仍要统一坐标原点、方向和单位。缺角照片不要强行按完整场地标定。

查看校正效果：

```powershell
& $robotPython .\windows\field_view.py preview $robotFrame.FullName --config $robotCalib
```

换机位、变焦、取流分辨率或画面旋转后重新标定。命令会覆盖 `$robotCalib`；需要保留各场标定时，将初始化中的路径改为本场独立文件。

## 7. 用场地标定实时查看车体位姿（不动车）

标定文件存在且相机设置与标定一致时：

```powershell
& $robotPython .\windows\capture_hi.py --scrcpy-dir $robotScrcpy --rotate 90 --max-size 1280 --no-fallback --config $robotCalib --detect-hz 10 --out $robotCaptureDir
```

显示场地校正图和 tag 位置/朝向，不发送底盘指令。仍使用 `pose_tag.py` / `tag_detector.py` 的实时路径，非最新离线曝光补检。

离线测一张标定原图的 tag 位姿：

```powershell
& $robotPython .\windows\pose_tag.py $robotFrame.FullName --config $robotCalib
```

## 8. 照片手动标注与查看现有结果（不启动相机）

第一批带车 13 张：

```powershell
& '.\windows\标注场地照片.cmd'
& '.\windows\查看场地识别结果.cmd'
```

第二批无车 7 张：

```powershell
& '.\windows\标注无车场地照片.cmd'
& '.\windows\查看无车识别结果.cmd'
```

每次仅执行所需的一条。标注中：`B` 点可见红块中心，`K` 点地面四角，右键撤销当前模式最后一点，`V` 标为已核对，`N/P` 保存并切图，`Q` 保存退出。tag 已近似居中且朝向车头，无需标 `C/F`。无车 01 缺真实地面角，不重猜四角。

## 9. 最新算法离线识别整批 JPG（不动车）

无车样本，读取该目录保存的有效四角；结果写本次新目录，保留旧报告：

```powershell
$robotBatchDir = '.\windows\test_data\field_no_robot_20261103'
$robotResultDir = ".\log\daily_runs\$robotSession\no_robot"
& $robotPython .\windows\detect_field_batch.py --input $robotBatchDir --output $robotResultDir --expect-no-robot
```

不使用人工四角、单独查看自动边界效果时，在命令末尾加 `--ignore-labels`。`--expect-no-robot` 仅记录预期状态，不关闭 tag/车身检测。

有保存红块标注时，做一对一漏检/多余候选评估：

```powershell
& $robotPython .\windows\evaluate_field_batch.py --predictions "$robotResultDir\detections.json" --input $robotBatchDir --output "$robotResultDir\evaluation"
Invoke-Item "$robotResultDir\detections_contact.jpg"
Invoke-Item "$robotResultDir\evaluation\errors_contact.jpg"
```

纯检测图绿=红块候选、黄=tag、青=场地边界；对照图绿=匹配、红=漏检、品红=多余候选。候选数不是已确认物块数。

跑带车旧样本时，将 `$robotBatchDir` 改为 `.\windows\test_data\field_photos_20261103`，`$robotResultDir` 改到本次独立目录，并去掉 `--expect-no-robot`。新 JPG 文件夹同样用 `--input` 指定，四角/红块标注应在其自身 `annotations.json` 内。

此批处理目前只遍历 `*.jpg`；不会自动把高分辨率 PNG 截图转换成该批次。PNG 的单张 tag 检测使用第 7 节。

## 10. 连续帧诊断：块数跳变/漏检定位（不动车）

不标注、只记录。没有 `field_calib.json` 时自动走台架模式（tag 50 mm 换算 mm/px），有标定时走与任务入口相同的场地链路：

```powershell
& $robotPython .\windows\record_diag.py --scrcpy-dir $robotScrcpy --secs 15 --save-frames
```

结果在 `windows/captures_hi/diag_时间/`：`frames.csv` 为逐帧判决（tag 是否解码、分界线是否找到、红候选数、单块面积估计、拆分实例数、每块坐标），`summary.json` 提供整帧作废比例、块数为 0 的帧占比、相邻帧块数变化中位/P90、同块位置抖动中位/P90 与失效原因分布。先检查整帧可用帧比例，再检查块数变化与抖动；这两类问题无法通过增加标注改善。默认不打开窗口，加 `--show` 才显示画面，且会降低分析频率。加 `--track` 会在同一段录像中同时记录合并/确认/平滑后的块数，便于对照。

## 12. 底盘工具入口与只读信息

查看 Windows 串口：

```powershell
& $robotPython -m serial.tools.list_ports
```

打开底盘工作台（之后的连接、控制操作由人选择）：

```powershell
& '.\tools\启动新面板.cmd'
```

`tools/核对固件版本.cmd` 实际比对的是电脑上的固件源码与归档包，不是读取车上当前固件版本。

串口工具已连接正确底盘后，以下是发送给 MCU 的文本，**不是 PowerShell 命令**：

```text
WHO
CAPS
POLARITY
STATUS
LAYOUT?
CAL?
```

紧急停止文本：`STOP`。应由已连接的串口工具发送；这里没有另开串口发送，以免与现用控制器抢占端口。

本车轮位为 `ADBC`；队友包文档中的 `CBAD` 不适用于本车。上电后的 `MODE CHASSIS` / `LAYOUT ADBC 1 1 1 1` 是配置操作，实机联调时结合底盘状态执行。

## 14. 红块训练集：采帧、框选、导出（不动车）

先把手机直接拍的照片收进数据集（按蓝黄方向统一成黄上蓝下，改名、去重、写清单；`111` 原图不动）：

```powershell
& $robotPython .\windows\import_photos.py --src 111 --out .\windows\test_data\red_photos_20261110
```

要多批数据只对一个目录标注/导出，把它们并进主数据集（复制、预填框、合并 `labels.json`、记 `sources.json`，源目录保留）：

```powershell
& $robotPython .\windows\merge_dataset.py --target .\windows\test_data\red_train_20261110 `
  --source .\windows\test_data\red_photos_20261110 --prefix photo
```

老批次只有中心点标注时，用 `import_points.py` 按 20 mm 边长扩成框再并入（框是推算的，仍需逐个确认）：

```powershell
& $robotPython .\windows\import_points.py --batch .\windows\test_data\field_no_robot_20261103 `
  --target .\windows\test_data\red_train_20261110 --prefix norobot
```

采帧（接手机，只存图，不发控制指令）。静态场地用**手动模式**：预览窗口里摆好一批按 `S` 存一帧、`Q` 退出：

```powershell
& $robotPython .\windows\collect_red_frames.py --scrcpy-dir $robotScrcpy --manual `
  --out .\windows\test_data\red_train_20261110
```

也可直接双击 `windows\红块采帧.cmd`。定时模式去掉 `--manual`，使用 `--interval 0.7 --seconds 180`，会自动跳过重复帧。每段使用单独目录；更换光照、机位或场景后重新拍摄一段。`manifest.json` 记录每帧红色像素数。仅需含红块的帧时加 `--min-red-px 50`；采集负样本时不添加。**朝向默认自动判断**（`--rotate auto`）：按蓝黄地面重心将画面统一为“黄上蓝下”，手机横放或竖放均无需手动调整；无法判定时报错退出。

框选标注（双击 `windows\红块框选标注.cmd` 也可；将其他 `frames` 文件夹拖到脚本上即可标注对应段）：

```powershell
& $robotPython .\windows\label_boxes.py .\windows\test_data\red_photos_20261110\frames
```

左键拖框、右键删框、`Z` 撤销、`D` 清空、`N`/空格/`V`/回车 **确认并下一张**、`U` 取消确认、`P` 上一张、`S` 保存、`Q` 退出。窗口按屏幕自动铺满，`+`/`-` 缩放。采帧时会用 HSV 自动预填框，标注主要是删误检、补漏检；旧帧可加 `--prefill` 补框。无红块的帧直接确认，作为负样本；未确认的帧不会导出。

导出 YOLO 结构（训练在别的机器上做）：

```powershell
& $robotPython .\windows\export_yolo.py .\windows\test_data\red_train_20261110 --val-every 5
```

生成 `yolo/images|labels/{train,val}` 与 `data.yaml`，单类 `red_block`。按文件名取模划分，相邻帧不会横跨训练/验证。双击 `windows\打包训练集.cmd` 打成 `training\red_train_yolo.zip`，再按 `training\colab_train.ipynb` 在 Colab 训练；拿回 `best.onnx` 后用 `windows\detect_onnx.py` 测 CPU 延迟。

拿人工标注当标准答案，比较 HSV 与 ONNX（IoU 0.3 一对一匹配）：

```powershell
& $robotPython .\windows\evaluate_detector.py --frames .\windows\test_data\red_train_20261110\frames --detector hsv
& $robotPython .\windows\evaluate_detector.py --frames .\windows\test_data\red_train_20261110\frames `
  --detector onnx --model .\windows\models\red_block.onnx
```

只有 ONNX 的 F1 不低于 HSV、单帧 < 100 ms，才在 `run_task` 上加 `--detector onnx` 试用。

## 容易混淆的快捷键

- `capture_hi.py`：`S` 保存，`R` 旋转，`Q/Esc` 退出，没有照片标注的 K 功能。
- `usb_camera.py` 旧预览：`K` 是**红块颜色校准**，`F` 是旧场地/色标检测开关，`B` 是红块检测开关；不能用 F 表示启用新版 ArUco。
- 照片标注入口：`K` 才是**点场地四角**，`B` 是点红块中心。
- `field_view.py calibrate`：按指定顺序点四角，回车保存。
