## 4. Windows 启动方法

### 4.1 摄像头独占与 USB

手机已开启 USB 调试并授权，用支持数据传输的 USB 线连接；保持解锁。原生 scrcpy、Python 客户端、Android IP Camera、自带相机、扫码/视频通话可能争用摄像头，同一时刻只运行一个采集客户端。

出现 `CAMERA_IN_USE` 先排除占用，不要反复安装依赖。可在 scrcpy 目录查看占用：

```powershell
.\adb.exe -d shell dumpsys media.camera | Select-String 'Active Camera Clients' -Context 0,20
```

### 4.2 原生 scrcpy：低延迟基准

```powershell
Set-Location 'E:\scrcpy\scrcpy-win64-v5.0.1'
.\adb.exe -d shell am force-stop com.github.digitallyrefined.androidipcamera
.\scrcpy.exe -d --video-source=camera --camera-facing=back --max-size=1280 --camera-fps=30 --video-codec=h264 --no-audio --orientation=90
```

使用方确认直采延迟可接受，最初方向相差90°。`--orientation=90` 为顺时针转90°，反方向用270；左Alt+左右方向键可在窗口内旋转。最终固定采用90还是270没有另外确认。这里直接采摄像头，并不是投手机相机界面；Windows 上显示 scrcpy 窗口不等于自动建立 `cv2.VideoCapture(0)` 虚拟摄像头。

### 4.3 Python/OpenCV 客户端

依赖已经安装。关闭原生 scrcpy 视频窗口后，日常执行：

```powershell
Set-Location 'E:\robot_competition\windows'
& 'E:\scrcpy\scrcpy-win64-v5.0.1\.venv\Scripts\python.exe' .\usb_camera.py --scrcpy-dir 'E:\scrcpy\scrcpy-win64-v5.0.1' --rotate 90
```

只有首次安装/重建环境才执行：

```powershell
py -3.12 -m venv 'E:\scrcpy\scrcpy-win64-v5.0.1\.venv'
& 'E:\scrcpy\scrcpy-win64-v5.0.1\.venv\Scripts\python.exe' -m pip install -r 'E:\robot_competition\windows\requirements.txt'
```

`-r` 和 `requirements.txt` 必须在同一条命令里，文件名不能单独运行。无需执行 `Activate.ps1`。

源文件与工具现已分目录，必须传 `--scrcpy-dir`；脚本默认会在自身目录寻找工具。新项目没有创建 `.venv`。本次仅核对路径及离线入口，不启动手机采集；迁移后的手机画面仍需使用方验收。

### 4.4 当前程序实际行为

- 自写客户端启动官方 scrcpy-server，创建独立 ADB 转发，经 USB 接收 H.264，再用 PyAV 软件解码、OpenCV 处理，不截取窗口。
- 后置摄像头，最大边1280、30fps、H.264、8Mbps；没有音频或手机操作控制通道。
- 接收解码在线程中持续进行，主线程只取最新帧，不积累待识别队列。
- **预览与识别仍运行在同一条最多10Hz循环**，保持比例旋转缩放并加黑边至640×480；模块拆分不等于显示/识别分频优化。
- 红块检测默认开启，B独立开关；F只开关场地/车体定位。K校准真块顶面；R旋转；C清除场地锁定；S同时保存原图和标注图；Q/Esc退出，支持大小写字母。
- S在 `E:\robot_competition\windows\captures` 保存同一时间前缀的 `*_raw.png` 与 `*_annotated.png`。原图不带标注，标注图包含当前已开启模块的框、箭头及状态文字；关闭F不影响红块框和保存。两张均为**已旋转缩放且可能带黑边的640×480 PNG**，不是原始传感器分辨率图。
- Windows预览对四角取周边轮廓再画绿框，不直接按单应性配对顺序连线，避免数字8形交叉框。要求候选场地内实际蓝/黄各占至少10%、合计至少55%，拒绝稀疏彩线被形态学闭运算连成的假场地；这只是初步过滤，不能替代真实场地标定。
- `red_blocks.detect_red_blocks(bgr, config=None)` 独立返回像素中心、边框、面积、轮廓及形状指标。无配置时最小面积20像素、形状阈值0.65/0.80/0.90；USB入口会自动加载 `red_block_profile.json`，因此运行参数可能不同。`RedBlockConfig` 独立配置，不依赖场地。
- K拖框选真块顶面的内部红色区域，Enter确认、Esc取消。`calibrate_red_config` 根据样本S/V分布生成带余量的饱和度和亮度范围，按包含选区中心的已知块面积的10%设置较宽松的最小面积（至少4像素），启用3×3小缺口闭运算，并将形状阈值放宽到0.65/0.72/0.80。配置保存后立即生效，下次启动自动读取；相机尺度或光照明显变化需重新校准。
- 初始 `red_block_profile.json` 来自原图 `field_20261022_031805_775500.png` 真块顶面选区(335,170,15,12)，参数为S86～188、V至少159、面积至少122.35像素。该选区只用于一次校准，不是运行时位置规则。该配置针对当前桌面拍摄条件，不能直接当作最终1.2m场地标定。
- 无论场地开启、关闭或失效，只要红块开关开启就显示通过颜色及形状筛选的绿色 `block?` 框。场地关闭显示 `FIELD OFF`，开启但无效显示 `FIELD NOT FOUND`。筛选已排除三张样本的车轮，但仍非通用物体分类；相似外观、遮挡和粘连需要另验。
- 默认形状筛选面向独立近方块，粘连长条或严重透视变形可能漏检；虽然坐标适配保留堆块尺寸范围，不能据此称默认检测已覆盖堆块。`RedBlockConfig(shape_filter=False)` 保留仅颜色诊断入口，不作为默认结果。
- `field_vision.detect_field` 仅计算场地/车体/障碍。`scene_vision.inspect_image` 组合两路，只有有效场地才把独立候选换成米制坐标及蓝黄归属；像素框不因此被删除。B关闭时己方计数为未知（-1），不当作清空。
- `PC age` 只是电脑解码后到处理的时间，不是曝光到显示的端到端延迟。
- 新解码帧超过0.35秒不更新时退出；这不等于已实现 ESP32 断联停车。
- **不连接 ESP32，不执行比赛策略，不发送运动指令**。
- 参数为 `--scrcpy-dir`、`--serial`、`--rotate`、`--field`、`--no-blocks` 及新增 `--red-profile`。后两者分别关闭启动时红块检测、指定实物配置路径。尚不存在 `--preview-fps` 等低延迟新版参数。

### 4.5 2026-10-22 桌面照片排查

收到 `windows/captures/field_20261022_031805_775500.png`、`field_20261022_031807_892700.png`、`field_20261022_031820_969700.png` 三张用户实拍，画面为灰色桌面，没有完整蓝黄场地及规定车顶色标。

## 5. 当前延迟问题与接续方案

已知：原生 scrcpy 延迟被认为可接受，Python 版仍略高。没有量化总延迟、实际显示/采集帧率、CPU负载或F开关对照结果。

源码确认的候选开销：

1. 10Hz主循环目标周期100ms，可能产生0～约100ms更新等待；这不是已测的总延迟。
2. 原始 H.264 流经 `CodecContext.parse()` 找帧边界；离线测试观察到末尾访问单元可能保留到后续字节到来。这是候选因素，尚未在手机上定量验证。
3. 软件解码、颜色转换、旋转缩放、可选HSV也有开销，阶段耗时尚未测量；不能把全部延迟都归到10Hz。

建议工作顺序：

1. 同一镜头/分辨率/光照/方向，对比原生scrcpy、Python F关闭、Python F开启，一次只运行一个客户端。
2. 用手机拍摄电脑动态计时器，比原计时器与回传画面读数，记录多次结果与条件，不用 `PC age` 冒充总延迟。
3. 分开预览与视觉识别频率：感知默认仍640×480、10Hz，预览可随采集更新；保持最新帧策略，不额外渲染大图。
4. 对照 **scrcpy5.0.1** 协议评估按完整编码包解码，减少字节流边界等待。5.x存在会话/配置/关键帧标志，不能照搬旧协议或随意跳过字节。此方案只检查过官方源码，**未写入程序**。
5. 据阶段耗时再评估采集分辨率、转换开销、硬件解码。USB线、TLS或Python版本不能在无证据时直接认定为根因。

目录整理后的Windows修改包括预览校验、绘框、保存、红块模块拆分、形状筛选及实物颜色/尺度校准，没有执行以上延迟优化，也没有修改外部scrcpy目录。

## 6. 已排查故障，避免重复绕路

| 现象 | 已确认情况/结论 |
|---|---|
| Android IP Camera 凭据未配置 | 开启认证但用户名/密码为空；后来配置。交接不保存密码 |
| 同应用HTTP429 | 触发认证限流；未携带凭据也可能计入，不能单凭429说密码一定错 |
| `HTTP=000`超时 | 一次确认为强制停止后忘了重开手机应用；ADB转发不会启动服务器 |
| Android IP Camera `200 bytes=0` | 0.14.0/API31；TLS与认证可通，MJPEG/H.264无数据，Camera1尝试未解决，手机有预览；**根因未明，目前使用scrcpy** |
| 按名称/PID取logcat信息少 | 不能据此认定没有采集或编码错误 |
| Python `CAMERA_IN_USE` | 明确提示高优先级客户端占用；排除占用后使用方确认跑通 |
| 首轮采集后 `Camera disconnected` | 日志含frame436后多次捕获失败；首次断开的具体占用者/底层根因未确认，未完成长期稳定性验收 |

Android IP Camera 旧路径为 `adb forward tcp:4444 tcp:4444` 和本机HTTPS接口；TLS不是有线连接必须关闭的选项。当前scrcpy/Python不依赖4444转发，也不需要该应用账号；不要把已停用的HTTPS接口当当前入口，也不要将该应用失败写成HarmonyOS确定不支持。

## 7. 现场视觉、坐标和比赛约束

- 场地1.2m×1.2m，围栏约10cm，蓝黄各半；己方蓝区为y<0，黄色方向为场地+y。车从蓝区底边出发、车头朝黄区；90秒内己方剩块更少为目标。

- 用俯视OpenCV HSV，不用YOLO，不在无GPU虚拟机训练。己方归属按红块周围地面蓝黄颜色，不把四边形几何中心当颜色中线。
