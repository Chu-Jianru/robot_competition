## 第 4 页｜运动调试台与 PI 固件

**English**

This is the motion workbench, shown disconnected. The firmware uses encoder counts to estimate wheel speed. Feedforward supplies the base PWM, P responds to the current error, and I compensates persistent error. The formula combines these contributions. PI is implemented, but this car still needs calibration and logs of target speed, measured speed and PWM.

**中文**

这里展示的是运动调试台，当前没有连接设备。固件通过编码器计数估计轮速，前馈提供基础占空比，P项响应当前误差，I项补偿持续偏差，公式表示三者共同形成控制输出。PI已经在固件中实现，但本车还没有完成标定，后续要记录目标轮速、实际轮速和占空比，再评价控制效果。

## 第 7 页｜Tag 定位与场地映射

**English**

For localization, we use ArUco ID zero from the four-by-four dictionary, with a fifty-millimetre side. Its black-and-white code reduces conflicts with the colored floor and blocks. Four corners provide the center and heading. To express this pose in field coordinates, we need a fixed overhead camera and four-corner perspective calibration.

**中文**

小车定位使用4×4字典中的ID 0 ArUco标记，边长50毫米。黑白编码可以减少与蓝黄地面、红色物块的颜色干扰。检测四个角点后，可以计算中心和朝向。要进一步得到场地坐标，还需要固定俯视相机，并通过场地四角进行透视标定。

## 第 8 页｜2 厘米物块检测

**English**

Block detection has three steps. First, HSV thresholds select red pixels, with saturation and brightness checks. Second, contour shape rejects fragments. Third, the known tag size estimates millimetres per pixel. Multiplying this scale by the square root of contour area gives an approximate block side, helping select candidates near two centimetres. The pictures show saved-photo detection results.

**中文**

物块检测分三步。先在HSV空间筛选红色，同时检查饱和度和亮度；再根据轮廓长宽比、矩形填充率和实心度排除碎片；最后利用tag的已知边长估计毫米与像素的比例。轮廓面积开平方后乘以这个比例，就得到近似等效边长，用于辅助筛选约2厘米的物块。左图展示的是实拍图片的离线检测结果。

## 第 9 页｜位姿到运动指令

**English**

Navigation compares the target pose with the current pose, then converts field-coordinate errors into the robot’s forward and left directions. For example, a target to the robot’s left requires leftward movement. Heading error determines the turn. The controller first aligns heading, sends a short movement pulse, stops, and reads a fresh pose before deciding the next action.

**中文**

导航先比较目标位姿与当前位姿，再把场地坐标误差转换到小车自身的前后、左右方向。例如，目标在小车左边，就需要向左平移；车头朝向与目标朝向之间的差，则决定转向动作。当前程序先调整朝向，再发送一个短时运动指令，停车后重新获取位姿，再决定下一步。

## 第 10 页｜指令时序与停车

**English**

Before movement, missing pose or pose older than zero-point-three-five seconds requests STOP. The ninety-second deadline also stops further movement. The link gives STOP priority and holds new jog commands during an action or cooldown. PC navigation has about a one-second cooldown, while the firmware PI update is a separate ten-millisecond loop.

**中文**

运动前先检查停车条件。没有有效位姿、位姿超过0.35秒未更新，或比赛达到90秒时，都请求停车。通信层优先处理STOP，并在动作执行或冷却期间阻止新点动。PC导航的冷却约为1秒，而固件PI约10毫秒更新一次，两者是不同层次的控制。

## 第 11 页｜策略简要回顾

**English**

The strategy remains the one presented previously: push regular rows east, then clean north along the wall. If rows disperse or become blocked, switch to local cleanup. Own blocks are identified using nearby floor colors. Pushing uses the front, with clearance checked before turning. The current task is connecting measured poses and real dimensions to this policy.

**中文**

策略沿用上次方案：规则整排先向东推送，再沿墙向北清理；队形散开或受阻时转入局部清理。己方物块根据附近地面颜色判断，推送依靠车头，转向前检查净空。当前重点是把实测位姿和实车尺寸接入这套策略，不再重复展开路线。

## 第 12 页｜下一步实物测试

**English**

Our next test is one block pushed across the midline, with synchronized pose, command and stop records. Before that, we need wheel calibration, load balancing, fixed-camera field calibration and continuous detection checks. This single-block test will show whether perception, navigation and chassis control work together on the physical robot.

**中文**

下一步的具体目标是完成一次单块越线推送，并同步保存位姿、指令和停车记录。为此，要先完成轮速标定、调整受力分布、固定相机标定场地，并检查连续检出。通过这次单块测试，验证视觉、导航和底盘能否在实车上配合工作。
